# System Specification: Shopaholic 循证购物决策顾问交互与推理体系重构

## Problem Statement

用户在借助 AI 进行购物决策与消费咨询时，现有的购物推荐系统存在以下核心体验与逻辑缺陷：

1. **澄清阶段时序因果倒置与假定好恶死锁**：
   在用户提出初步或模糊的选购需求时，系统在第一轮提问中就过早地抛出了关于“输出排版格式与交付视角（如全局排序、分场景矩阵、硬性特征黑名单剔除）”的元决策问题。由于用户此时尚未陈述自身的好恶与痛点，系统在生成“黑名单剔除”选项时不得不自行脑补或假定某些具体偏好（如翻转屏、碎镜风险等）。这导致用户面临认知过载，产生“我还没有表达好恶，选项却已经预设了我的偏好，选了不对，不选也不对”的决策死锁与困惑。
2. **软场景偏好与硬物理红线混淆导致跨界品类机械误杀**：
   系统容易将用户的探索性偏好（如“想要下巴机位拍沉浸感”、“平时一个人骑行”）等同于不可逆的物理硬红线，教条化执行淘汰逻辑，导致用户同时想探索的跨界品类（如全景相机、多功能形态设备）在初筛阶段被 100% 机械误杀。
3. **静态预训练记忆导致的品牌事实性幻觉**：
   系统过度信任内部静态权重，在面对用户针对具体品牌或新兴产品线的质询（如“大疆有没有全景相机”）时未做防御性检索，自信断言“该品牌无此产品”，向用户输出严重过时的虚假信息并进行错误说教。
4. **大样本证据一刀切抹杀高规格新品与供应链黑马**：
   系统过分苛求大样本长期用户追评，导致刚发布的高用料旗舰新品或供应链扎实的性价比黑马被简单粗暴地判定为“不可信”或直接降级淘汰，无法满足极客与追求前沿体验用户的选购诉求。
5. **面对用户事实纠错时的情绪化谄媚与两极反转**：
   在被用户纠错或指出最新机型后，系统极易发生 180 度态度反转，从傲慢否定转为无原则盲目吹捧，丧失了对新品软件成熟度、批次一致性与早期品控风险的客观审视能力。
6. **用户发生形态跃迁与约束漂移时缺乏代价守恒闭环**：
   当用户中途推翻先前约束（如从便携轻薄形态切换为重载专业形态）时，系统往往顺从迎合，未主动向用户揭示新方案在工作流摩擦、物理力矩安全、算力要求以及易损 TCO 上的四维新增代价。

---

## Solution

构建一套**渐进式偏好建构、智能视角自适应、防御性全网核验、双轨证据分档与四维代价守恒**的完整循证决策支持系统：

1. **时序解耦的两阶段偏好诱导状态机（Two-Phase Elicitation State Machine）**：
   - **Turn 1（纯净画像与好恶萃取）**：首轮提问 100% 聚焦于真实使用工况、物理硬约束（尺寸/空间/预算）以及主观痛点与敏感点，严格禁止出现任何关于输出格式、排版模式或抽象黑名单的元控制问题，杜绝空集假定与认知过载。
   - **Turn 2（画像回显与智能视角自适应推荐）**：在报告中先结构化回显提取出的用户画像；系统根据画像特征**自动匹配最佳交付视角**（多场景矩阵 / 黑名单前置排除与决战 / 综合优先级双轨排名），支持智能默认与按需微调，无需用户在空白状态下盲选。
2. **硬物理红线与软场景偏好严格解耦**：
   - 确立仅允许物理尺寸绝对超标、安装空间干涉、致命安全缺陷等 H 类硬红线执行候选池一票否决；
   - S 类软场景偏好仅作为权重加权因子或多场景分栏展示的依据，彻底保全跨界探索品类。
3. **强制时效性防御检索与全谱系拉网扫描**：
   - 禁止凭内部记忆断言产品存在性，针对品牌与具体型号质询强制触发多角度时效性防御检索；
   - 推荐前执行头部主流、高潜新锐与专业代工源头的全谱系拉网扫描（10~15 款宽池），确保覆盖最新在售产品。
4. **双轨证据分档架构（A 档成熟池 + B 档新品黑马池）**：
   - 最终呈现 6~10 款代表性机型，平行划分为“A 档大样本成熟验证池”与“B 档高潜能硬核新品池”；
   - 对 B 档机型强制置顶输出【成熟度与售后妥协声明】，完整披露早期品控与软件迭代风险。
5. **冷峻抗谄媚与事实接入规程**：
   - 纠错时保持高位顾问人设，执行“中立接入 -> 独立取证 -> 重新跑通矩阵 -> 给出软硬件综合客观评价”，杜绝道歉与谄媚。
6. **约束漂移时代价守恒定律（Cost of Pivoting）**：
   - 场景跃迁时强制置顶输出工作流、动力学、算力与易损 TCO 四维新增代价清单，帮助用户理性评估方案切换成本。

## User Stories

1. As a 选购需求较为模糊的消费者, I want 系统在第一轮只询问我平时的使用工况、预算和最在意的痛点, so that 我不需要在还不懂品类知识时去纠结复杂的输出排版或抽象的黑名单选项。
2. As a 初次接触某品类的新手, I want 系统的第一轮提问完全基于通俗的生活与工作场景（Usage-related questions）, so that 我能轻松作答而不会被专业技术参数轰炸。
3. As a 既想用于日常通勤又想用于极限游玩的跨界用户, I want 系统在了解我的双重需求后，自动为我分场景罗列推荐方案, so that 我不会因为选了通勤偏好而导致适合极限工况的产品被一刀切淘汰。
4. As a 对特定缺点（如翻转屏易坏、某类材质发黄）极度排斥的用户, I want 系统在获知我的厌恶点后，自动生成专门的排除清单并针对幸存机型决战, so that 我能清晰看到为什么某些热销款被淘汰。
5. As a 需求单一且目标明确的用户, I want 系统自动以全局综合排名的形式给出首选方案与备选阶梯, so that 我能最高效地获取购买建议，无需多余的操作步骤。
6. As a 想要确认最新数码动态的极客, I want 询问某品牌是否有某类新型产品时系统强制去全网最新信源检索, so that 系统不会因为模型记忆过时而告诉我“该产品不存在”。
7. As a 关注市场全面竞争态势的理性买家, I want 系统在推荐前拉网扫描主流大厂与新锐黑马的完整在售图谱, so that 推荐报告不会遗漏最具性价比的新发布型号。
8. As a 愿意尝鲜最新硬核配置的技术爱好者, I want 在推荐报告中看到专门划分的【B 档新品/黑马观察池】, so that 我能获知最新旗舰的硬件用料，同时清楚知晓其软件与售后可能存在的初期妥协。
9. As a 追求绝对省心耐用的普通家庭用户, I want 在【A 档成熟验证池】中挑选具备海量长期好评与完善售后网络的商品, so that 我不必承担任何早期品控波动的风险。
10. As a 发现系统信息有遗漏并主动提供型号补充的用户, I want 系统冷静接入数据并给出客观严谨的优缺点分析, so that 系统不会因为被纠错而陷入无原则的吹捧与虚伪道歉。
11. As a 在选购过程中突然改变主意（如推翻机位或形态）的用户, I want 系统在给出新方案前强制列出【前置代价确认】, so that 我能清晰意识到形态跃迁带来的后期处理繁琐度与配件开销增加。
12. As a 关注商品长期使用成本的消费者, I want 推荐报告列明单次耗材成本与易损件维修 TCO, so that 我不会购买到“买得起但用不起”的商品。
13. As a 关注健康与安全的特殊品类买家, I want 系统在涉及母婴、食品、医疗器械时强制核验法定资质与国家标准, so that 我能获得符合法定法规的底线安全保障。
14. As a 对话式系统的开发者, I want 拥有一套完整的端到端行为测试与消融基准, so that 我能用量化指标验证时序解耦、防御检索与代价守恒等机制的有效性。

## Implementation Decisions

### 1. 偏好诱导与交付呈现的时序状态机架构

系统与用户的多轮交互必须严格解耦为两个不可逆的顺序阶段：

```
[用户初始输入] ──► [Turn 1: 纯净画像与好恶萃取] ──► [用户回答场景与痛点] ──► [Turn 2: 画像回显 + 智能视角自适应推荐]
```

- **Turn 1 交互契约**：
  - 仅触发 2~3 个场景与痛点问题；
  - 核心属性聚焦于：使用频率、环境条件、协同设备、预算区间、以及最不能忍受的痛点（如“最怕重”、“最怕复杂剪辑”）；
  - 严禁出现任何涉及“输出报告格式”、“表格呈现方式”、“是否使用黑名单剔除”等元控制选项。
- **Turn 2 交互契约**：
  - 在决策报告第 2 节完成画像与好恶的回显；
  - 由系统规则引擎自动推断最匹配的呈现视角：
    - 若画像包含跨界/多重使用工况矛盾 $\rightarrow$ 自动采用 `视角 ②（分场景矩阵表）`；
    - 若画像包含明确厌恶的物理特征/品牌 $\rightarrow$ 自动采用 `视角 ③（黑名单前置排除表 + 幸存者决战表）`；
    - 若画像需求单一聚焦 $\rightarrow$ 自动采用 `视角 ①（综合优先级全局双轨排名表）`；
  - 报告开头附带一句话智能视角适配说明，支持用户根据需要随时提出调整。

### 2. 约束解耦与准入过滤原则

- **H 类硬物理红线（Hard Invariants）**：
  - 包含：物理尺寸绝对超出预留空间、安装结构干涉、供电制式不兼容、国家强制认证缺失、官方召回缺陷；
  - 规则：**仅 H 类变量允许用于候选池的一票否决与绝对剔除**。
- **S 类软场景偏好（Soft Preferences）**：
  - 包含：机位喜好、便携倾向、色彩风格、品牌好恶、特定功能尝鲜；
  - 规则：**S 类变量绝对禁止用于物理级剔除**，仅作为权重加权因子或分场景矩阵的分组维度。

### 3. 防御性检索与拉网扫描规程

- **防御性检索拦截器**：凡用户提到具体品牌 + 具体功能，或就具体型号发起质询，系统必须前置发起 $\ge 2$ 轮带当前年份的多角度检索，禁止依赖内部记忆直接断言。
- **3+2+1 谱系拉网扫描**：推荐前必须扫描 3 个主流大厂、2 个新锐先锋与 1 个代工/极客源头，候选池初始扫描规模达 10~15 款。
- **双重佐证底线**：核心候选商品必须同时具备 L1 级（法定标准/官方规格）与 L2 级（独立第三方拆解实测）数据。

### 4. 双轨证据分档与风险披露

- **A 档成熟池（Mainstream Validated）**：上市时间长、销量达标、具备大样本用户长期追评与独立拆解验证（3~5 款）。
- **B 档新品/黑马池（Emerging Speculative）**：核心硬件 BOM 完全白盒化、经拆解证实做工扎实，但上市时间短或保有量较小（3~5 款）。
- **强制声明**：B 档表格下方强制置顶输出【成熟度与售后妥协声明】，明确提示算法迭代、大样本一致性与售后网络局限。

### 5. 抗谄媚与四维代价守恒

- **反谄媚规程**：用户纠错或提出新候选时，保持冷静客观，执行“中立接入 -> 独立取证 -> 重新跑通矩阵 -> 给出软硬件综合客观评价”，禁止道歉与讨好。
- **四维代价守恒**：用户推翻先前约束或发生形态跃迁时，强制在输出新方案时置顶输出工作流摩擦、动力学与安全、算力与终端解码、以及光学/机械易损 TCO 四维新增代价清单。

## Testing Decisions

### 1. 测试原则与好测试的标准
- 测试必须专注于**端到端外部可观测行为（External Observable Behavior）**，而非内部实现细节；
- 重点验证：
  - 首轮交互是否保持纯净（无元格式问题、无假定好恶）；
  - 第二轮是否正确识别画像并自动采用对应的交付视角；
  - 跨界品类是否被正确保全；
  - 事实性检索是否能准确召回最新型号；
  - 形态跃迁时是否完整披露四维代价。

### 2. 测试场景与验证套件
- **场景一（摩托车骑行记录设备选购）**：测试跨界单面与全景设备共存、防御性检索召回最新全景机型、Turn 1 纯净提问、Turn 2 自动分场景/双轨分档、以及改装车头延长杆时的四维代价输出。
- **场景二（洗烘设备与大家电选购）**：测试独立热泵与冷凝一体形态跃迁、预留尺寸硬红线核查、耗材与清理代价披露。
- **自动化消融实验（Ablation Benchmark Suite）**：执行多子代理自动化评测，检验移除防御性检索、移除两阶段解耦、移除双轨分档或移除代价守恒时的量化指标下降情况。

## Out of Scope

1. 接入需要个人私有登录凭证或加密 Cookie 的封闭电商平台内部下单接口。
2. 非消费品选购领域的纯代码开发、学术论文翻译或创意写作任务。
3. 替代具有法定资质的专业医师提供医疗诊断建议。

## Further Notes

本规范确立了对话式购物决策顾问在人机交互与专业推荐上的核心标杆，通过时序解耦与渐进式偏好建构，兼顾了交互自然度与专业严谨性。
