# System Specification: Shopaholic 循证购物决策顾问深度重构规范 (v2.0)

## Problem Statement

用户在借助 AI 进行购物决策时，现有的选购支持体系存在以下深层次的交互体验、检索时序与选品逻辑缺陷：

1. **仓库级/工程级 Skill 安装方案缺失**：
   现有的安装指引与脚本仅覆盖了操作系统全局 Agent 目录（如全局 Claude Code、Pi 或全局配置），缺乏在当前 Git 仓库或项目工程根目录下以项目级（Repo/Project-level，如 `.agents/skills/shopaholic`、`skills/shopaholic`）一键集成与本地化配置的完整方案。
2. **第一轮检索过早死板过滤预算导致优质候选严重漏召回**：
   当用户在第一轮提出模糊需求（例如“想买个 2000 左右的微单/运动相机”）时，系统往往在甚至还没搞清楚品类技术全貌时，就直接以“2000 元”作为硬过滤条件去检索。这导致大量原本素质极高、技术代际领先但官方售价略高（但在二手市场恰好在预算内）的经典机型，或者品类底层核心物理标准被直接漏掉，严重限制了后续推荐的视野深度。
3. **缺少真正的第二轮质询与二手/下架经典款偏好确认**：
   在第一轮提取完用户的工况和痛点后，系统缺乏第二轮结构化质询闭环：
   - 未向用户确认期望的交付视角（全局排序、分场景矩阵、黑名单决战）；
   - **完全遗漏了“是否支持二手/已下架经典款”的核心质询**。很多数码、摄影、家电品类中，上一代旗舰或已停产的经典型号在二手市场性价比极高、做工扎实，但如果用户有“绝对不要二手”的洁癖，则必须严格限定为在售一手全新机。缺乏该询问会导致选品建议与用户真实消费心智产生严重脱节。
4. **跨轮次检索割裂与证据脱水深度不足**：
   各轮对话中的搜索缺乏跨轮次的知识沉淀与漏斗聚合机制。系统在第二轮生成建议时，容易丢弃第一轮已经搜到的品类标准与技术知识，未能在第二轮补充检索后进行全量证据融合，且缺乏对社区软广、导购水军的深度脱水过滤。
5. **预训练记忆幻觉与形态跃迁隐性代价缺失**：
   系统在面对具体品牌质询时容易产生断言不存在的幻觉，并在用户发生形态漂移（如从单面相机换为全景相机）时迎合省略四维代价。

---

## Solution

构建一套**仓库级即插即用、全价格带前置广度探索、双轮递进质询与跨轮次深度循证聚合**的完整决策体系：

1. **仓库级与跨运行时一键安装体系（Repo-Level & Multi-Runtime Integration）**：
   - 增强安装器 CLI 与文档，支持将 `shopaholic` 一键注入到当前 Git 仓库（Local Repo Mode：`.agents/skills/shopaholic` 或 `skills/shopaholic`），与项目代码库协同版本管理，同时兼容系统级全局 Agent 目录。
2. **三阶段认知漏斗与双轮质询状态机（Three-Stage Cognitive Funnel & Dual-Inquiry Machine）**：
   - **Stage 1 (Turn 1 前置广度探索 ──► 工况与痛点质询)**：
     - *全谱系广度检索*：在提出任何问题前，先不设价格和渠道过滤，全网检索品类法定国标、底层科学原理、权威社区讨论（Chiphell/酷安/硬核实测）以及全价格带代表性产品，建立品类完整技术供给基准；
     - *Turn 1 纯净质询*：基于广度知识，向用户提出 2~3 个关于实际使用工况（环境/频率/搭配设备）、物理硬约束（尺寸/空间）与主观痛点敏感点的问题，严禁提前抛出排版元格式问题。
   - **Stage 2 (Turn 2 定向补盲检索 ──► 交付视角与一手/二手偏好质询)**：
     - *定向补盲检索*：根据用户回答的工况痛点，针对性检索特定细分技术路径与最新行情；
     - *Turn 2 核心质询*：向用户发起第二轮质询：
       - ① 确认报告交付视角（① 综合优先级全局排序 / ② 按细分场景矩阵罗列 / ③ 明确痛点黑名单排除）；
       - ② **确认商品来源偏好（二手/停产经典款支持度）**：明确询问是否接受“成色优秀的二手/已停产高性价比经典旗舰”，还是仅限“官方渠道在售一手全新正品”。
   - **Stage 3 (Turn 3 / Final 跨轮次深度挖掘 ──► A/B 双轨循证决策报告)**：
     - *跨轮次深度聚合检索*：全量合并 Turn 1 + Turn 2 获取的所有候选与知识，针对最终入围机型发起 L1 官方规格 + L2 独立仪器拆解实测的深度探针，穿透 BOM 用料与致命暗病，严格过滤商业软广与返利链接；
     - *双轨报告呈现*：结合二手/一手偏好与选定视角，输出 A 档成熟池与 B 档观察池（附妥协声明）的完整决策报告。
3. **防御性时效检索（Phase 0）与 3+2+1 谱系覆盖**：
   - 禁止静态记忆断言，品牌质询强制发起 $\ge 2$ 轮时效性（2025/2026）检索；
   - 候选初筛池保持 10~15 款宽池，最终精选 6~10 款代表实体。
4. **冷峻抗谄媚与形态跃迁四维代价守恒**：
   - 纠错保持中立冷静，形态跃迁强制置顶核算工作流摩擦、动力学安全、算力解码与易损 TCO 四维新增代价。

## User Stories

1. As a 开发者或团队技术负责人, I want 能将 `shopaholic` 一键安装到当前项目的仓库根目录中（Repo-Level）, so that 团队成员在当前仓库内打开 AI 编码助手或智能体时能直接共享该技能。
2. As a 想要咨询购物但预算有限的用户, I want 在第一轮提出模糊预算（如“2000 左右”）时系统不被死板价格卡死，而是先去广度检索整个品类的技术标准、科学原理和全谱系产品, so that 系统具备真正的行业大局观，不会因过早过滤而漏掉优秀机型。
3. As a 购物咨询用户, I want 系统在第一轮前置检索中深入查阅专业社区（如 Chiphell、酷安、专业拆解）的真实讨论, so that 第一轮向我提出的问题能精准击中该品类的核心物理矛盾与痛点，而不是问一些外行废话。
4. As a 需求尚未完全明确的用户, I want 第一轮问题 100% 聚焦于我的生活与工作实际场景, so that 我无需在还不懂品类技术时去纠结复杂的输出排版格式。
5. As a 回答了第一轮工况的用户, I want 系统在第二轮向我发起专门质询，询问我是否接受“二手或已停产的经典性价比旗舰”, so that 如果我愿意买二手，系统能帮我把预算的性价比发挥到极致。
6. As a 有洁癖、绝不接受任何二手翻新商品的用户, I want 在第二轮质询中明确表达“只要在售一手全新正品”, so that 最终推荐报告中绝对不会出现任何已下架或二手平台的机型。
7. As a 在第一轮表达了多重使用工况（如通勤+长途旅行）的用户, I want 在第二轮质询中选择“按细分场景矩阵罗列”交付视角, so that 最终报告不会因为某个单项偏好而误杀适合另一场景的跨界好物。
8. As a 讨厌某些特定结构（如翻转屏、笨重机身）的用户, I want 在第二轮质询中选择“黑名单前置排除”, so that 报告能直接展示被淘汰的机型及淘汰技术归因。
9. As a 追求高信度决策的理性买家, I want 系统在生成最终报告前，全量聚合第一轮与第二轮的搜索结果，并深入核验独立仪器拆解数据（L2）和真实客诉, so that 推荐结果彻底免受电商刷单好评和知乎/小红书导购软文的污染。
10. As a 关注市场最新旗舰的极客, I want 在最终报告中看到【B 档：高潜能·硬核新品/黑马观察池】以及醒目的【成熟度与售后妥协声明】, so that 我能清晰了解新品在用料扎实的同时可能存在的早期软件与售后妥协。
11. As a 追求绝对稳妥的普通家庭用户, I want 在【A 档：大样本成熟验证池】中挑选经过长期市场检验的机型, so that 我买后省心、无需承担品控风险。
12. As a 询问“某品牌是否有某款新型产品”的用户, I want 系统强制执行多角度最新年份检索, so that 系统不会因为模型旧记忆而误判该产品不存在。
13. As a 主动给系统纠错或提供新机型的用户, I want 系统以中立数据接入姿态独立核验并客观剖析优缺点, so that 系统不会产生情绪化自责或无原则吹捧。
14. As a 选购中途改变核心形态（如单面相机换全景相机）的用户, I want 系统强制置顶列出【前置代价确认】, so that 我能清晰意识到新形态在工作流繁琐度、算力要求与配件 TCO 上的新增负担。

## Implementation Decisions

### 1. 仓库级与多运行时本地安装架构

- **CLI 增强**：在 `bin/cli.js` 中增加 `--local` 或 `--repo` 参数，并支持通过命令行一键安装至当前工作区的 `.agents/skills/shopaholic`、`.claude/skills/shopaholic`、`skills/shopaholic`；
- **自适应检测**：根据当前仓库根目录存在的配置文件（`.git`、`package.json`、`claude.json`、`omp.json`）智能判断最合适的本地存放路径；
- **文档统一**：在 `README.md` 与 `README_EN.md` 中置顶增补“仓库级/项目级本地安装方案”。

### 2. 三阶段认知漏斗与双轮质询时序状态机

系统执行严密的“两轮质询、三阶段递进”状态机：

```
[用户提出模糊需求] 
       │
       ▼
【Stage 1: 前置广度探索与工况质询】
  ├── Step 1.1: 全品类/全价格带广度前置检索 (国标/科学原理/社区硬核讨论/全谱系扫描 10~15 款)
  └── Step 1.2: Turn 1 纯净质询 (提取 2~3 个使用工况、物理硬约束与痛点好恶，严禁元格式侵入)
       │
       ▼ (用户回答工况与痛点)
【Stage 2: 定向补盲检索与交付/二手偏好质询】
  ├── Step 2.1: 定向补盲检索 (根据工况补充特定技术路线、价格带与停产经典款行情)
  └── Step 2.2: Turn 2 核心质询 (通过提问工具同时确认：① 交付呈现视角 + ② 一手/二手与停产经典款偏好)
       │
       ▼ (用户回答交付视角与二手偏好)
【Stage 3: 跨轮次深度挖掘与最终决策交付】
  ├── Step 3.1: 跨轮次深度聚合检索 (合并全量候选池，穿透 BOM 拆解、致命客诉，过滤水军软广)
  └── Step 3.2: 输出 A/B 双轨对比矩阵与完整循证决策报告 (依交付视角与一手/二手偏好自适应呈现)
```

- **Turn 1 交互契约**：仅允许提出 2~3 个关于真实生活工况与主观痛点的问题，严禁涉及任何排版格式；
- **Turn 2 交互契约**：必须明确包含 2 个关键维度的质询：
  - ① 交付视角：全局优先级双轨表 / 细分场景矩阵表 / 黑名单剔除决战表；
  - ② **一手/二手与停产经典偏好**：【A 仅限官方在售一手正品】/ 【B 欢迎高性价比成色优秀二手/经典停产款】/ 【C 两者皆可，同台竞技】。

### 3. 全价格带广度搜索与跨轮次证据聚合引擎

- **前置广度检索原则（Broad Discovery Invariant）**：
  - 第一轮检索**严禁预设价格上限或下限**；
  - 检索目标为：品类强制国标（GB/T）、底层物理限制（如传感器尺寸/散热面积/电机功率）、行业硬核社区（Chiphell/酷安/无忌）共识与全价格带 10~15 款代表产品。
- **跨轮次证据聚合与脱水规则（Cross-Turn Aggregation & Anti-Pollution）**：
  - Turn 3 必须全量聚合 Stage 1 与 Stage 2 发现的所有候选实体；
  - 核心候选必须经过 L1 法定标准 + L2 独立仪器拆解实测的双重佐证；
  - 严格剔除带分销返利参数、情绪化形容词（“闭眼入/神仙好物”）的商业软广。

### 4. 双轨证据分档与全生命周期 TCO 披露

- **A 档大样本成熟验证池**（3~5 款）：上市 $\ge 6$ 个月，大样本追评与全国联保；
- **B 档高潜能新品/黑马观察池**（3~5 款）：BOM 白盒化 + 独立拆解证实做工扎实，强制置顶输出【成熟度与售后妥协声明】；
- 若用户在 Turn 2 选择支持二手，则在对比表格中明确标注“一手参考价”与“优质二手行情价/渠道避坑”。

## Testing Decisions

### 1. 外部可观测行为测试
- 验证仓库级安装命令是否能正确将 Skill 安装至当前项目的 `.agents/skills` 或 `skills/`；
- 验证第一轮交互前是否触发全品类广度检索且无价格窄化过滤；
- 验证 Turn 1 是否纯净（仅工况痛点）；
- 验证 Turn 2 是否准确同时发起“交付视角”与“二手/下架经典款支持度”的质询；
- 验证 Turn 3 是否完整聚合跨轮次搜索结果并输出双轨决策报告。

### 2. 消融评测套件更新
- 更新 `scripts/ablation-suite.js`，加入对全品类广度前置搜索、Turn 2 二手/视角双重质询与跨轮次证据聚合的自动化评测与量化断言。

## Out of Scope

1. 接入私有电商账号直接代客下单扣款。
2. 违规破解私有反爬虫接口。
